# 日报生成与追问

适用：用户要求生成某天板块日报、询问昨日热门、打开日报或追问其中讨论。

1. 先用 `read_forum_profiles` 核对板块。相对日期按 Asia/Shanghai 换算为 YYYY-MM-DD，说明具体日期。缺少必要日期或板块时先澄清。
2. 用户要求生成日报时调用 `create_daily_issue(target_day, forum_ids)`。只提交确切范围，等待界面批准；工具使用当前会话所有者，不能指定其他 session 或 owner。后台会检查覆盖并可能创建补抓任务，不是纯本地统计。
3. 返回 queued/job_id 只说明已提交。用 `read_daily_issue(issue_id)` 读取执行尝试、覆盖限制和成稿版本；可用 `wait_for_jobs` 等待返回的 Job，再核对期次。不把失败、部分覆盖或等待归档说成完成。
4. 日报主体是当天新增讨论：同时包括当天新帖和旧帖当天新增回复。旧正文仅作背景；专楼按当天议题整理，按当日讨论衡量活跃度，不用累计回复数替代。
5. 成稿应呈现具体信息、观点、分歧与原文证据，合并关联帖子，避免仅复述统计榜单。没有阅读历史不能断言某观点首次出现或立场发生改变。
6. 已绑定日报版本的 Run 用 `read_daily_report` 读取冻结快照，说明日期、板块、覆盖情况和版本。`read_daily_issue` 的新版本不会改变本 Run 冻结快照。
7. 日报中的来源标识不是本 Run 的原文阅读回执。需要引用楼层事实时重新用 `read_discussion_source` 阅读并校验；区分既有事实、当下远端状态和推断。
8. 一次生成不会创建定时规则；定时需求使用独立调度能力。不要在一次性日报请求中自动创建周期任务，也不要遇到失败就自动反复补报。
