## 1. 产品决定：两个入口，一个工作过程

**助手负责理解需求、执行受控任务和解释结果；知识库负责找回讨论、日报和其他成果。后台任务仍由现有 Job 系统执行。**

首个完整版本覆盖四个场景：

| 场景 | 用户操作 | 必须得到的结果 |
|---|---|---|
| 查资料 | 找到归档，选若干帖子，要求总结/比较 | 回答、具体来源、实际已读范围和遗漏说明 |
| 做任务 | 请求归档、更新或导出一组对象 | 可追踪的 Job 回执、阶段和失败原因 |
| 看日报 | 指定板块和每日时间，自动生成昨日讨论热门信息 | 有日期、来源、排序理由和运行状态的日报，可查看历史与追问 |
| 留成果 | 将有价值的回答保存，稍后继续研究 | 可再次打开、编辑、导出、查看来源和继续对话的研究笔记 |

日报与研究笔记分别命名：日报由保存的规则和指定日期生成，研究笔记由用户选择保存和编辑。内部笔记可使用 note/note_revision 命名；现有趋势报告继续保留自身名称与用途。

主使用路径：

```text
选定讨论 / 提出问题 ──→ 助手读取、回答 ──→ 按需保存整理
设定每日板块与时间 ──→ Daemon 生成日报 ──→ 知识库查看、继续追问
指定归档 / 导出对象 ──→ 授权并创建 Job ──→ 任务卡与最终文件
```

继续使用 React、FastAPI、PostgreSQL、现有 Daemon 和应用层。首版新增受限研究优先落在 embedded；Hermes 保留现有功能，通过能力字段控制新入口。上线前确认实际后端模式，不能静默切换用户部署。[当前 Chat 接口](../../src/yamibo_mcp/web_fastapi/routers/chat.py#L15)、[Hermes 能力探测](../../src/yamibo_mcp/services/web_chat.py#L15)。

首版范围之外：全库自动主题发现、动态资料集订阅、无人值守长期研究、邮件发送、通用定时规则平台、插件市场、知识图谱和外部向量数据库。固定范围的每日讨论日报属于首版任务，详见补充方案。语义检索可继续作为增强，但首版闭环不能依赖它。

## 2. 页面怎样改

### 2.1 助手：主区看过程，侧区看依据

导航“对话”改为“助手”，保留 /chat 地址。桌面为会话列表、主对话、可展开的资料/成果面板；窄屏面板改为抽屉或独立详情，当前任务状态始终在主区。

主区顺序：

1. 范围条：例如“本地归档 · 已选 5 篇 · 回复时间 2024—2025”。
2. 对话和执行卡：先显示理解到的对象，随后显示真实读取或 Job 进度。
3. 结果：回答带引用，提供“查看来源”“保存笔记”。
4. 输入区：空闲时继续输入；运行时明确显示“加入下一条请求”，停止按钮单独放置。

主区先做四种业务卡片：

| 卡片 | 字段与动作 |
|---|---|
| 资料卡 | 标题、可用原文、已读楼层/PID、未读或缺失内容；打开原文、移除或补读 |
| 任务卡 | 目标、stage、已处理/总量、最后更新时间、重试/失败原因；打开任务详情、完成后继续 |
| 日报卡 | 目标日、板块、生成状态、资料范围、热门条目预览；打开当期日报或规则 |
| 笔记卡 | 标题、版本、来源数、正文预览；保存、打开、继续讨论 |

JSON、工具参数、事件数和模型调试信息进入“技术详情”。任务百分比仅在业务层有可靠分母时显示。模型写的“已经处理一半”不作为进度来源。

空白页展示“查归档资料”“归档或更新”“查看任务”三个示例；例子只来自当前后端实际能力。没有最近任务查询工具时，不展示相应承诺，先补分页查询接口。[当前欢迎页](../../c/src/pages/Chat.tsx#L167)、[工具白名单](../../src/yamibo_mcp/services/embedded_chat/mcp.py#L25)。

### 2.2 知识库：先看讨论与日报，把维护移出首屏

保留 /rag 兼容入口，建议内部组织如下：

| 视图 | 首版内容 |
|---|---|
| /rag：讨论与日报 | 搜索讨论入口、最新及历史日报、运行失败提示、我的整理；空态引导设置板块和生成时间 |
| /rag/daily/:id：日报详情 | 昨日概况、热门讨论、当日回复引用、数据范围、报告版本；打开原帖和继续追问 |
| /rag/notes/:id：笔记详情 | 正文、引用、版本切换、Markdown 编辑/预览、导出、继续对话 |
| /rag/maintenance：索引维护 | 复用旧 Rag 页的索引任务、覆盖诊断、模型参数和检索调试 |

页面地址是拟议路由。资料查找复用 /threads 的筛选、选择和阅读器，增加“交给助手”；知识库只提供入口，不复制另一套帖子管理。[已有路由](../../c/src/App.tsx#L40)、[已有选择状态](../../c/src/pages/Threads.tsx#L78)。

日报列表、资料入口、笔记和维护统计独立加载。统计超时不能让整个知识库只剩 Loading。各区域有各自的加载、错误、重试和数据更新时间。首版用现有组件和主题，不同步重做全站视觉系统。

## 3. 执行契约：让用户知道正在发生什么

### 3.1 分开业务状态和连接状态

| 状态对象 | 建议状态 | 规则 |
|---|---|---|
| 访问 | 加载中、需要令牌、未配置、不可达、可用 | 401 不显示“未配置”；错误保留准确恢复动作 |
| 本地提交 | 提交中、已接受、提交失败 | 点击即展示；失败复用相同请求标识重试 |
| Run | 排队、执行、等待确认、等待短任务、完成、失败、停止/受限 | 以服务端为准，沿用现有终态语义 |
| 连接 | 在线、重连、离线 | 离线不将 Run 强制变成业务终态 |
| Job | 使用现有 Job 状态和进度 | Run 完成后，已关联 Job 仍独立刷新 |

现有提交晚反馈、错误字段不一致和重连耗尽缺口分别见 [Chat.tsx](../../c/src/pages/Chat.tsx#L110)、[ChatToolEvent.tsx](../../c/src/components/chat/ChatToolEvent.tsx#L1)、[useChatRunStream.ts](../../c/src/hooks/useChatRunStream.ts#L37)。实施以复现这些边界的测试起步。

标准工具结果至少包括成功与否、业务错误、结构化 data 和结果引用。旧 result.error 与顶层 error 在前端入口归一化；新增版本字段时保留旧事件回放适配，避免旧对话失去展示能力。

### 3.2 长任务首版明确交接

在普通交互请求中，创建长期归档 Job 后立即显示回执并结束本轮模型执行；任务卡继续跟随 Job。全部达到约定完成条件后，显示“继续分析”，由用户点击发起新的 Run。若用户要求“完成后自动总结”，只有创建了持久化续作任务才可承诺自动继续。定时日报使用独立保存的规则和后台流程，不靠保持聊天 Run 运行到第二天。

短等待可以保留，但必须有可配置上限；到时转交接，不长期占用模型运行名额。停止助手阻止后续推理和新工具调用，明确列出仍在运行的 Job；后台暂停/取消遵循任务系统现有能力。

后续确有无人值守需求时再增加持久化续作：前置 Job、成功/部分成功条件、冻结范围、后续指令、预算、幂等键和状态。由现有 Daemon 唤起新 Run，测试重复通知和重启恢复。当前等待占槽依据见 [runtime.py](../../src/yamibo_mcp/services/embedded_chat/runtime.py#L384)。

## 4. 两页共享什么数据

### 4.1 研究范围：附在会话，创建 Run 时冻结

首版范围只支持“已选帖子”，可附回复发表日期。无选择的普通助手可以找候选资料，但进入受限分析前，要把实际对象明确显示并固定下来。

建议范围结构包括：

- schema_version、scope_revision；
- source=local、selected_tids；
- 可选发表时间区间、time_field=post_published_at、timezone=Asia/Shanghai；
- policy=fixed、可引用的笔记版本；
- 来源会话和可选 parent_note_revision。

会话保存下一次请求的默认范围；Run 接收并冻结范围副本，运行中修改选择只影响后续请求。更换资料范围默认开关联新会话，避免旧对话中的范围外材料继续进入模型证据。

embedded 可复用现有 sessions/runs JSON 存储；API 使用显式结构校验，不能把任意 JSON 原样信任。当前 Store 和请求模型分别见 [store.py](../../src/yamibo_mcp/services/embedded_chat/store.py#L54)、[chat.py](../../src/yamibo_mcp/web_fastapi/routers/chat.py#L15)。

**幂等校验需随之升级。** 当前重试主要比较输入文本；新契约比较输入、冻结范围及关联笔记版本。同一 request_id 携带不同范围返回冲突，不能返回旧范围的 Run。[当前 start_run](../../src/yamibo_mcp/services/embedded_chat/runtime.py#L230)。

范围由服务端注入并取交集，搜索与原文读取都执行约束。不能仅把 TID 列表放入提示词。严格研究模式也限制远端工具、任意工作文件和旧笔记读取，避免其他入口绕过范围；已有笔记是派生上下文，不能自动变成论坛原始证据。归档写操作的授权另行沿用现有 Policy，研究范围不等于写权限。

### 4.2 证据：记录“实际读到”，不只记录“搜到”

每次成功读取由宿主记录回执，至少有 evidence_id、tid/pid、楼层、原作者与时间、读取范围、内容哈希、读取时间、是否截断。引用 ID 从这些回执生成，模型不能凭空创造有效来源。

首版把有界读取回执归入现有 Run 事件；保存笔记时复制所需证据到笔记版本，避免未来清理聊天记录导致笔记引用丢失。大段原文不重复嵌入每个事件；对记录总量和读取字符数设可配置上限。

候选结果、已读材料、正文引用分开展示。保存前检查引用 ID 是否存在且属于本 Run 范围；无效引用阻止发布为“已核对来源”，仍可保存为带警告草稿。程序校验只能保证引用结构与范围，不能代替对结论含义的核验。

首版保存引用原文片段、位置和哈希，以及完整的有界读取清单；**不承诺完整重放模型看过的全部长帖**。若以后要求严格复现，再增加完整读取材料快照。仅有帖子 ID 或哈希而没有正文副本，不足以恢复历史原文。

### 4.3 研究笔记：新增两张小表，正文只有一个权威来源

| 对象 | 核心字段 | 不变量 |
|---|---|---|
| knowledge_notes | id、title、current_revision、关联 session、创建/更新时间 | 主记录负责列表和当前版本指针 |
| knowledge_note_revisions | note_id、revision、Markdown、冻结范围、引用快照、读取清单、来源 Run、parent_revision、作者类型、限制说明、保存请求标识 | 已保存版本不可变，正文与证据同事务保存 |

版本表对 (note_id, revision) 唯一，保存请求标识也有相应唯一约束。保存/编辑带 expected_revision，冲突时保留草稿并要求选择基准，不覆盖另一处编辑。重复保存同一请求返回原版本。

人工编辑形成新版本；模型重写先生成候选，用户采纳后新增版本，不静默更新当前人工正文。没有来源的手工内容可以保存，但明确标记为人工补充。

不把这些笔记硬塞进趋势报告表：其 (run_id, report_kind) 冲突会更新现有内容。[报告仓储](../../src/yamibo_mcp/db/repositories/discussion_trends.py#L584)。工作文件已有 revision/hash 校验，可复用相同原则与底层安全工具，但笔记正文以数据库版本为准，Markdown 文件只是导出。[工作文件实现](../../src/yamibo_mcp/services/embedded_chat/files.py#L205)。

“从笔记继续”默认携带所选版本和范围创建关联会话，笔记作为派生上下文，关键论据按需重新读取原文。旧会话可查看，但不盲目注入全部历史。原文删除或变化时，保留旧片段并提示状态。

## 5. 检索和索引怎样演进

### 首版：选定资料直接读取，先把边界做对

标题/分区筛选复用现有归档能力；对已选帖子调用原文读取，按批次处理。正式原文接口目前使用 offset 游标，不能假定在归档变化中稳定：[archive_queries.py](../../src/yamibo_mcp/application/archive_queries.py#L100)。

研究读取需增加稳定游标或版本检测：游标绑定 scope_revision、最后排序键和本次读取上界；读取过程中发现源内容变化，标记来源混合版本并停止宣称完整覆盖。实现选择以现有楼层存储能力为准，验收必须覆盖分页期间新增与编辑回复。

日期按楼层发表时间过滤，采用明确的半开区间 [start, end)，用户选择的结束日转换为下一日零点。缺少时间的材料不进入严格时间窗；如允许背景材料，另列且不计入范围统计。过滤必须先于排序及 Top K 截取，并覆盖 keyword/vector/SQL/fallback 和直接读取。

修复入口：[楼层分块](../../src/yamibo_mcp/rag/chunker.py#L110)、[研究主检索](../../src/yamibo_mcp/application/discussion_trend_queries.py#L633)、[二次 fallback](../../src/yamibo_mcp/application/knowledge_queries.py#L435)。未通过范围契约的旧组合查询，不开放给首版“仅分析已选资料”。

读取超出工具、时间或字符预算时，返回已读和未读范围，允许保存部分结果并继续；不默默扩预算。图像页和无法提取的文本标为不可读，首版不暗含 OCR 能力。

### 第二阶段：让文本检索成为正式能力

将“准备文本”和“生成向量”拆成可独立运行的正式 Job 模式。先为选定范围准备文本，不全库重建。已有[纯文本演练](../../scripts/demo_knowledge_text_pipeline.py#L48)可作为样例与函数复用参考，不能用演练脚本操作生产。

替换文本分块采用事务或新代切换，失败保留旧可用版本。向量仅在内容哈希、分块规则、模型身份均一致时复用；文本变化后旧向量失效。关键词能力不受单一向量开关控制。

所有检索返回 requested_mode、actual_mode、applied_scope、degraded_reason 和 coverage。无结果、索引未准备、索引过期、服务失败分别表达。coverage 的分母是本地范围内可处理材料，不是全论坛；未知时写未知。[当前门控及降级](../../src/yamibo_mcp/application/rag_queries.py#L34)、[现有索引计数](../../src/yamibo_mcp/db/repositories/rag_chunks.py#L194)。

语义检索按模型身份隔离，不仅检查维度；配置身份不清楚的旧向量不能默认与新模型混用。[向量实现](../../src/yamibo_mcp/db/repositories/postgres_vectors.py#L60)。中文相关性改进先用真实问题评测，再决定检索实现，不预先增加依赖。

全局趋势走定义清楚的数据库聚合；Top K 只提供候选证据，不提供总体频率或分母。主题归因和跨年代结论不作为首版默认承诺。

## 6. 最小接口与实现边界

以下是拟议接口，不是已有 API 清单：

| 接口/能力 | 用途与校验 |
|---|---|
| Chat context 增加 capabilities | 返回 scoped_research、knowledge_notes、job_receipts；前端按实际能力展示 |
| 会话更新 scope，Run 提交 scope_revision | 版本冲突返回 409；冻结范围并纳入幂等键语义 |
| Run evidence 查询 | 分页读取宿主生成的证据回执；可断线重开 |
| GET /knowledge/notes 及详情/版本 | 分页列表，正文与维护统计独立 |
| POST /knowledge/notes 与版本创建 | 带保存请求标识、expected_revision、来源 Run；验证引用与范围 |
| 从指定笔记版本继续 | 创建关联会话，返回 session_id；重复点击使用请求标识去重 |
| 关联 Job 读取 | 从真实工具回执绑定，复用现有 Job 读接口；前端批量、有限频率更新 |

知识笔记查询、保存和导出沿用 Chat 的访问令牌保护；单用户场景无需新增账号系统，但不能把私人笔记挂到未鉴权的新路径。令牌不放入 URL、证据或日志。

应用逻辑放 application 的 commands/queries；新笔记仓储放 db/repositories；路由只做参数校验和调用。扩展当前 knowledge 路由时保留旧 research/trend-index/research-report API，不静默改变旧报告结果。[现有 knowledge 路由](../../src/yamibo_mcp/web_fastapi/routers/knowledge.py#L13)。

## 7. 按交付批次实施

### A：入口与反馈可靠，可独立发布

修改 Chat、useChatSessions、useChatRunStream、ChatToolEvent、ChatLocalPanel、Rag、API 请求客户端及相关事件生产路径。

交付：准确访问状态、失败退出 Loading、可重试超时、即时消息、错误卡、Job 卡、连接/业务状态分离。维护统计按需加载，隐藏面板停止不必要文件轮询。记录请求接收、排队、MCP 启动、首输出、工具与 Job 时间点；暂不大改运行器。

验收目标（是建议目标，不是当前测量值）：

- 故意延迟创建 Run 3 秒，本地消息在正常设备上 200ms 内显示“正在提交”；重复点击/重试只生成一个 Run。
- 401、无模型配置、503、断网分别有正确提示；区域请求 10 秒无响应显示超时和重试，不阻断其他入口。
- Job 状态仍为 running 但阶段改变，在一个约定刷新周期内展示；建议活跃页周期不超过 5 秒。
- SSE 重试耗尽再恢复，继续同一 Run 且不重复消息或创建 Job。
- 停止助手后，仍运行的 Job 有明确列表。

依据：[Rag 加载](../../c/src/pages/Rag.tsx#L66)、[概览路由](../../src/yamibo_mcp/web_fastapi/routers/rag.py#L18)、[Job 事件](../../src/yamibo_mcp/services/embedded_chat/mcp.py#L375)。

### B：归档/导出任务链与每日讨论日报

先让助手完成明确 TID 或经用户选定的讨论帖归档/导出，页面分别展示授权范围、Job 进度和可下载结果。再提供手动生成某日讨论日报：只取指定讨论板块，按当地自然日读取当日回复、排序候选、补读关键回复、记录实际读取回执，保存带来源和数据范围的报告。通过旧帖新回复、重复活动模板和后续更正样例验证内容选择。

手动日报验证后，加入保存的每日规则、Daemon 调度、日期去重、重启补跑、迟到资料/部分结果与历史版本。知识库新增日报列表和详情，对话支持创建、查看、暂停规则及追问某期报告。具体契约见[日报与归档导出能力修正](../讨论助手—日报与归档导出能力修正.md)。B 完成才称为本次目标的首个完整版本。

### C：研究笔记闭环

按依赖顺序实施：

1. 在 B 已实现的受限范围、日报来源与读取回执上，扩展笔记的引用契约；覆盖日期、稳定分页及预算。
2. 新增笔记两表、仓储、应用服务、鉴权与幂等保存。
3. 帖子列表接“交给助手”，主区加入资料/来源/笔记卡。
4. 在知识库的讨论与日报入口下增加“我的整理”；旧索引调试界面迁入维护视图。
5. 接入版本编辑、导出、指定版本继续讨论。
6. 按实际可用能力补齐最近任务查询和欢迎页示例。

核心修改入口见第 2、4、5、6 节。新增前端 Knowledge、KnowledgeNote 组件与笔记服务，按现有目录组织；不建立第二套 Chat 运行器。

验收：

- 不配置 embedding，短帖、长帖、多帖三个样例均可完成“选择→阅读→回答→保存→重开→继续”。
- 只选 5 篇时模型请求第 6 篇被拒绝；远端工具和任意文件入口也不能绕过范围。
- 同一 request_id 换 scope 返回 409；会话范围改变不改变已创建的 Run。
- 年末旧帖的新年回复按回复时间归类；缺时间楼层不混入严格年份结果。
- 分页间新增/修改楼层不会被静默认定为完整一致的阅读。
- 无效引用被识别；只读片段的结果明确标注部分分析。
- 重复保存无重复版本；并发修改触发冲突；人工版不被模型覆盖。
- 删除聊天或当前原文不可用后，保存的笔记正文及引用片段仍可查看。
- Hermes 无范围保障时不出现“严格按已选资料分析”的可用入口。

C 的笔记能力可独立发布，不作为日报和归档/导出交付前提。

### D：使用证明有价值后再增强

顺序建议：指定范围文本检索改进 → 打开笔记时检查来源变化 → 更复杂的长任务续作 → 语义检索质量与增量向量 → 邮件发送及通用定时规则扩展。每日讨论日报的固定规则与调度已列入 B。

来源检查区分已变更、当前本地未发现变化、未知/未检查；未经远端刷新不能声称论坛没有新内容。比较新增回复需有原研究范围及读取上界，仅比较已引用片段不够。

自动更新创建候选新版本和变化摘要，保留旧版。自动触发与邮件只消费已有可追踪成果，发送和生成分离，结果未知不能盲目重复外发。该阶段另按实际使用需求细化，不提前开发通用插件平台。

## 8. 迁移、风险及验证

| 风险 | 控制与验证 |
|---|---|
| 多入口绕过研究范围 | 受限工具集合、宿主注入范围；测试搜索/原文/文件/旧会话全部入口 |
| 引用格式正确但观点不成立 | 程序检查位置和范围；用真实短帖/长帖人工核对结论、反例与遗漏 |
| 旧索引字段不可信 | 查询关联原始楼层校准作者时间；旧索引状态标明限制；不先全量重算 |
| 两种正文存储互相覆盖 | 笔记数据库版本为唯一正文；工作文件保持独立；导出单向生成 |
| 迁移或刷新失败损伤旧资料 | 新增表、非破坏迁移；索引事务/新代切换；隔离库演练及生产备份 |
| 新功能在另一后端不可用 | capabilities 门控；发布前确认模式；不静默迁移 Hermes |
| 自动化过早扩大规模 | A/B 为首版发布范围；C 每次只交付一个有使用证据的需求 |

数据库迁移走项目初始化入口，不直接假定顶层 Alembic 命令可用。保留旧报告、旧聊天和旧索引；首版不自动导入全部历史工作文件。回退时关闭新入口，保留新增数据，不靠删表回滚。

验证分层：

1. 单元测试：请求幂等、范围交集、时间窗、引用、版本冲突、工具错误与状态映射。
2. PostgreSQL 集成：真实唯一约束、事务保存、并发更新、稳定读取；SQLite 单测不替代此项。
3. 浏览器：延迟发送、401、概览超时、断网恢复、Job 同状态进度、窄屏、保存后重开。
4. 真实模型样例：允许声明不了解与部分完成，人工核验来源支持关系；预设模型测试只证明线路。
5. 前端每次改动后构建静态资产，并检查差异；生产验证以部署版本和授权只读场景为准，代码推送不代表上线。

产品验收再加一条：用三个真实整理任务，至少有一份笔记在后续任务中被找回并继续使用。如果仍需复制帖子或重开空白聊天，先改“找回和继续”的路径，再投入专题与自动化。
