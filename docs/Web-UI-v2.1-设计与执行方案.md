# Yamibo Web UI v2.1：详细设计与执行方案

> 状态：P0–P5 已实施并按抽样页面完成视觉复核。日期：2026-09-23。设计决策以根目录 `DESIGN.md` 为准；本文负责页面规格、实施顺序和验收。具体证据与已知资源缺口见 `Web-UI-v2.1-视觉验收记录.md`。

## 1. 目标、依据与边界

目标是在保留「数字典藏、现代独立出版物」气质的同时，让归档、排障、检索和阅读成为界面的主角。视觉语言沿用暖纸色、炭墨字、深栗红操作色、细金分隔线和中日英混排字体。`ui渲染.png` 仅用于色彩、排版节奏和材质参考；其中的期号、栏目号、英文散文、火漆章和多组策展标签不构成产品功能要求。

依据：`DESIGN.md`、`docs/Web界面设计.md`、`ui渲染.png`、`c/src/App.tsx`、`c/src/components/Layout.tsx`、`c/src/index.css`、`c/src/styles.css`、核心页面源码，以及 2026-09-23 对本地服务的检查。P0 的抽样桌面宽约 1280px：首页标题列 112px、最后活动列 190px；归档标题列 210px；系列与导出表分别宽约 1563px 和 1808px；论坛列表版块与标签列各约 47px。这些是旧版样本值。**PC 验收基准改为用户当前 Chrome 窗口的实际尺寸与分辨率**，本次测得窗口截图为 1163×768 像素；1280×720 和 1440×900 仅作辅助响应式检查，不取代该基准。

本轮只设计现有路由和现有业务能力的界面。新增后端统计、推荐算法、收藏能力或图片恢复能力，须有真实数据契约后才作为功能上线。现有编辑、批量操作、归档、阅读、导出、索引和配置行为需要保留。实施时保留用户工作区中无关的未提交改动。

### 成功标准

1. 用户进入任一页面，首屏能分辨页面目的、当前状态和下一步主操作。
2. 帖子标题在桌面列表中至少保留两行或足够辨识的作品名与话数；手机界面不只剩 TID。
3. 页面级无横向滚动，且所有主要信息与操作仍可到达；宽表格可在明确标示的容器内滚动，或转换为卡片。
4. 关键错误、状态、帮助文字和控件在浅色、深色模式均可读；不能通过降低字号或隐藏溢出来制造“整齐”。
5. 标签、统计和操作只表达实际存在的能力，加载占位不伪装成真实数据。

## 2. 一致性设计规则

### 2.1 信息架构与导航

- 一级导航继续覆盖控制台、帖子归档、任务中心、知识检索、作品系列、论坛漫游、AI 对话、审核工作、导出中心、系统日志、配置中心。桌面可按「内容」「工作」「系统」形成轻量分组，但不改变路由；当前页和所在分组必须清楚。
- 桌面侧栏宽度约 208px，可手动折叠。低于 768px 默认关闭，改为菜单按钮打开的抽屉；打开时覆盖内容并可通过 Esc、遮罩点击和导航后关闭。品牌寄语只在展开侧栏保留一次，不在每个页面重复。
- 所有非首页页面统一页头：返回/面包屑（详情页）、H1、用一句话说明用途或当前对象、右侧主操作。技术 ID 可复制，显示在次级信息中，不代替标题。
- 首页不再重复侧栏品牌大字，不使用 `ISSUE #TID`、`SECTION 01` 等无业务含义的标签。

### 2.2 视觉与文字

- 全站颜色使用 `c/src/index.css` 的语义变量；业务页不直接复用旧版蓝色强调。正文用 sans，长文阅读用 serif，ID/时间/日志等短数据用 mono。中文页面以中文为主；专业英文缩写仅在需要精确诊断时保留。
- 页面标题建议 24–32px；区块标题 16–20px；正文和表格主体不低于 13px；辅助说明不低于 12px。9–10px 的字仅用于非关键装饰，关键状态不得用装饰字级。数字卡允许较大的数字，但单位必须紧邻数字且不换成竖排。
- 普通文本与背景至少满足 WCAG AA 4.5:1；大字至少 3:1；可交互边界和状态图形至少 3:1。错误文字以深色正文配浅色警示底，深色模式使用相应反转色；色彩不是状态的唯一信号。
- 长 URL、路径、Job ID 与 JSON 使用 `overflow-wrap:anywhere` 或局部可滚动代码块。日期列表显示本地化短格式；完整 ISO 值放在详情或提示中，不直接占用首页列表宽度。
- 按钮有主、次、危险三级；危险操作始终有文字标签或明确的可访问名称。禁用、加载、成功、失败与部分完成须有稳定的文字反馈。

### 2.3 标题列表与表格契约

标题是帖子与系列列表的第一信息，列宽优先于 TID、标签、第二时间列和路径。桌面 1280px 左右的帖子列表，标题目标宽度至少 320px；在更窄内容区使用两行布局或隐藏次级列，不固守像素值。标题默认两行裁剪，行高约 1.4；作品名、话数、章节号若位于末尾，不能只剩没有辨识度的通用前缀。完整标题可通过焦点可达的展开、详情页或独立按钮获取，不能仅依赖鼠标 `title` 提示。

表格由页面定义主列、次列和折叠顺序，不再通过全局 `table` 样式假设所有内容等价。表头可排序时展示当前方向和可操作状态。分页、筛选与列设置保持现有功能；用户自定义列宽与隐藏列应受最小标题可读性约束，并有“恢复推荐布局”。

| 视口 | 帖子/任务列表 | 宽数据表 |
| --- | --- | --- |
| ≥1280px | 标题/描述两行以内，主要列完整；次级时间可简写 | 按内容分配列宽，必要时局部横向滚动并提示 |
| 768–1279px | 先移除第二时间、标签、内部阶段等次列 | 表格局部滚动或切卡片，保持主列可见 |
| <768px | 卡片行：标题/任务描述、状态、TID、一个时间、主操作 | 明确的卡片或字段列表，不保留被裁去的桌面表 |

任何断点均不允许内容被页面级 `overflow-x:hidden` 静默截掉。选择框与危险操作不能覆盖标题；触控操作目标建议至少 44×44px。

### 2.4 状态与反馈

- Loading：使用与最终布局相近的骨架；不显示 `1,248,931`、虚构文章等样张数据。
- Empty：解释为什么为空，并给出下一步；“当前无待审核”与“加载失败”必须区分。
- Error：先给人可读的原因和行动建议，再按需展开技术原文；不得出现低对比错误卡。
- Partial：明确已完成与仍缺失的数量及后续操作；不能用普通“完成”徽章覆盖缺口。
- Offline/remote blocked：论坛漫游、图片和 AI 服务应说明远端/本地服务状态，不让不可用按钮继续呈现为正常主操作。
- 动效只用于导航、展开与状态反馈；`prefers-reduced-motion` 下无缩放或弹跳。任务状态不依靠呼吸动画传达。

## 3. 页面详细设计

### 3.1 控制台 `/`

用途：让用户知道归档是否健康，并快速回到最近内容或待处理任务。首屏顺序：紧凑页头 → 真实统计（归档帖子、作品系列、导出档案）与队列状态 → 待处理异常 → 最近归档/继续阅读。保留暖纸卡、衬线强调和细分隔线，删除巨型报头、期号、栏目号、四词口号、固定英文散文、火漆章与重复金句。`POPULAR`、`TRENDING`、`EDITOR'S PICK` 在拥有不同且可解释的数据源之前不显示；只保留“最近归档”和版块筛选。精选内容须由真实帖子摘要/封面构成，没有适用内容则显示普通最近阅读卡。`SAVE` 只在收藏能力确实存在时出现。

### 3.2 任务中心 `/jobs`

页头显示“任务中心”、总运行状态与刷新时间。状态筛选横向可滚动但不逐字换行，失败时展示错误类别筛选。行主标题是可理解的任务描述，如“为 #536025 补全图片”；状态、阶段、进度、时间是辅助信息；`image_backfill` 等内部类型可放在详情或技术提示。批量操作仅在选中后出现，注明作用范围；删除入口与恢复/重试隔开。移动端用任务卡，首屏显示描述、状态、当前进度与主要操作。

### 3.3 任务详情 `/jobs/:id`

首屏顺序：返回任务中心 → 人可读任务名和状态 → 关键进度/更新时间 → 最新阻塞原因与下一步操作 → 关联帖子 → 详细属性。错误卡将分类、发生阶段、短说明、技术原文分层。事件时间线默认按最近优先，先显示最近 10–20 条，可按失败/状态变更/全部过滤；完整 200 条历史可展开或分页。负载 JSON 默认折叠，长 URL 可换行。重试、继续、重新同步等仅在对应状态可用时出现，点击后反馈新任务 ID 与导航结果。

### 3.4 归档帖子 `/threads`

搜索与版块筛选在页头下，当前结果数和排序状态明确。桌面默认列：选择、标题、版块/内容类型、归档状态、回复、一个时间、操作；第二时间及标签由列设置或详情承载。标题左对齐、两行裁剪；TID 可作为标题旁的次级标识。保留当前列配置能力，但推荐布局必须保证标题优先。手机卡片显示完整或两行标题与状态，不出现“只剩复选框和 TID”的布局。

### 3.5 归档帖子详情 `/threads/:tid` 与阅读器

帖名作为可换行 H1；返回、阅读、更多管理操作分层。阅读预览在元数据总表之前；版块、系列、章节、作者、校验等归档字段折叠到“归档信息”，编辑入口保留。沉浸模式维持无顶栏和底部胶囊，阅读宽度为上限而非强制值；手机注意安全区与底部遮挡。图片流显示加载、缺失、可恢复、仅远端四种状态，不能让包含图片块的漫画帖看起来只有文字。内容块原始表放到调试/高级区。

### 3.6 作品系列 `/series` 与 `/series/:id`

列表主列为左对齐的系列名，作者、帖子数、复核状态作为次级列；系列键不与长名称争抢首屏。无名称、待复核的系列用明确状态说明。详情页以系列名作 H1，下面展示有序章节/帖子、作者和复核/合并操作；`目标ID` 等内部文案改为次级标识。合并与删除仍保留原有确认流程。

### 3.7 论坛漫游 `/forum`、`/forum/:tid` 与 `/forums`

列表主列为标题，次级行展示版块、标签、作者和发布时间；版块和标签不能被压成逐字竖排。横向筛选项太多时采用可滚动标签条并显示当前选择。远端详情以原帖标题为 H1；“原始标题/标题”相同时只显示一次，版块、作者、时间、归档状态使用简洁概览。阅读预览优先，归档操作清楚说明是创建任务而非立即完成。`/forums` 路由作为同一论坛体系纳入实施前视觉复核，不能未经检查就套用列表规格。

### 3.8 知识检索 `/rag`

将“搜索归档”和“索引管理”拆成页面内两个明确区段/标签。默认聚焦搜索：搜索框、范围、模式、结果及引用。索引管理展示覆盖率、失败数、模型与维度，统计卡要有标签与数值层级；创建/批量索引与监控列表在其下。`Top K`、`Chunk` 等专业词附简短说明。失败向量数可进入对应筛选，不做孤立数字。

### 3.9 AI 对话 `/chat`

保留会话列表和输入区，但统一纸墨色与深栗红主操作，清理旧蓝色强调。服务不可用时展示明确状态、原因和配置入口，输入和推荐卡按实际可用性禁用或降级；不会出现一边提示不可用一边邀请“新建会话”的冲突。长工具输出、文件名和引用在容器内换行或折叠。

### 3.10 审核 `/review`

页头显示待复核总数及类型。待办列表突出原标题/建议标题、差异、置信或规则线索和操作；空状态说明已完成，并提供查看最近处理记录或返回归档的入口。表格字段可展开查看，避免系列键和操作列同时挤压标题。

### 3.11 导出 `/exports`

标题为主列；状态、生成时间、目标文件名为次级信息。完整本地路径不直接撑开表格，默认显示尾部路径和复制完整路径按钮；路径缺失与文件不可访问是不同状态。详情或展开行呈现完整路径、格式与关联帖子。

### 3.12 系统日志 `/logs`

时间、级别、模块固定可扫读，消息列自适应；长 SQL、堆栈折叠展开，默认显示摘要。日志级别与筛选支持组合，暂停自动滚动在查看历史时保持明显。清空等操作与常用筛选分离，防误触。技术文本使用等宽字体，但日志正文仍保持足够字级和行距。

### 3.13 配置 `/settings`、`/settings/advanced`

按“归档抓取、任务调度、AI/RAG、界面与表格”分组；每个字段显示含义、当前值来源、保存后何时生效。已保存待重启等提示集中在页头并可定位受影响项；按钮状态统一为深栗红体系。高级设置清楚标识风险与守护条件，文案不因字小色淡而消失。保留现有逐组保存语义和权限门槛。

## 4. 执行方案

按依赖关系分阶段实施，每阶段完成后单独验收并保留可回退的改动。页面视觉验收以真实本地服务截图为准，构建成功只证明代码可编译。

| 阶段 | 主要工作与文件 | 完成门槛 |
| --- | --- | --- |
| P0 基线 | 记录主要路由在手机、平板和用户当前 Chrome 实际窗口的浅/深色截图与长标题样本；核对现有列配置和各页面业务操作。涉及 `c/src/App.tsx`、`c/src/components/Layout.tsx`、`c/src/components/TableLayoutEditor.tsx`、页面样本。 | 有页面抽样截图和用例清单；区分设计问题、数据问题和图片资源问题。 |

| P3 内容与诊断详情 | 任务详情诊断优先、事件过滤；归档/远端帖详情阅读优先；系列详情标题与章节；阅读图片状态。涉及 `JobDetail.tsx`、`ThreadDetail.tsx`、`RemoteThreadDetail.tsx`、`ThreadReader.tsx`、`Exports.tsx` 中系列详情。 | 首屏知道状态和下一步；样本 200 事件可快速定位最近失败；漫画图片状态可辨；原有操作流程可用。 |

| P5 回归与文档 | 对照设计契约复查所有页面类型；以用户当前 Chrome 窗口作 PC 基准，手机和平板为辅助；更新 `DESIGN.md`、`docs/Web界面设计.md` 和验收记录。前端源码改动后执行 `cd c && npm run build`。 | 构建通过；桌面与手机关键路径视觉检查通过；剩余缺口记录为明确问题，不以构建结果代替视觉验收。 |

### 必测交互与视觉用例

- 真实长标题：中文、日文、英文混排；前缀相同但卷次/话数不同；超长无空格标题。核对首页、归档、论坛、系列、导出和审核列表。
- 状态：成功、部分、失败、暂停、运行、加载中、空、服务不可用；错误含 URL、Job ID、JSON 和长 SQL。
- 阅读：文本帖、长图漫画、缺失图片、远端图片无法读取、沉浸模式进出与楼层跳转。
- 操作：搜索/筛选/排序/分页、批量选择与取消、任务重试/继续、归档、导出、配置保存；各操作需维持现有权限和确认流程。
- 视口与输入：用户当前 Chrome 实际窗口为 PC 主基准；390×844、768×1024、1280×720、1440×900 用于辅助断点回归；键盘、触屏和鼠标；浅/深色；系统减少动态效果。

## 5. 风险与待决事项

- **现有列设置与新默认布局冲突**：尊重已保存配置，但提供恢复推荐布局；必要时迁移仅默认值，不静默覆盖用户配置。
- **长标题无法靠固定宽度解决**：优先改信息密度与断点行为；单纯增大表格宽度会重现横向裁切。
- **业务数据与样张内容混合**：先删虚构占位；新增“热门/精选/收藏”前必须定义数据、排序及状态，不以视觉假功能代替。
- **图片缺失可能是数据、网络或阅读组件问题**：P0 先分类证据，P3 再决定界面状态与是否需要恢复能力；本方案不预断原因。
- **视觉验收以当前服务与抽样数据为界**：各页面的深色与窄屏样本见验收记录；后续如换用不同数据量、系统字体或浏览器缩放，应重测长标题和局部表格滚动。
