# 知识库纯文本演练

本演练用于验证现有能力如何串联，不是完整的新知识库实现。
使用真实 PostgreSQL、公共 stdio MCP、内置 `EmbeddedChatService`。
LLM 使用预设 `FunctionModel`；不启动 embedding 服务、不生成向量、不访问外部模型或论坛。

## 运行

在仓库根目录执行：

```bash
uv run python scripts/demo_knowledge_text_pipeline.py
```

使用当前配置的本地 PostgreSQL 连接，需要创建临时数据库的权限。
脚本只接受 `localhost`、`127.0.0.1` 或 `::1`，仅在随机命名的隔离库初始化表和写入样例，结束时删除该库。
不会升级原数据库，也不启动 Daemon 或消费已有任务。

- 默认样例：`data/threads` 中的 553545、36025、572373。
- `--sample-root`：更换样例根目录，仍须包含上述三个帖子。
- `--output`：报告目录；默认在系统临时目录生成并保留 `report.json` 和 `summary.md`。
- 脚本复用同目录 `demo_knowledge_pipeline.py` 的样例导入、MCP 响应读取与模拟 Agent 辅助函数，但不执行其 embedding 演练。
- 源文件保持不变；只在隔离库按时间排序并重新编号楼层，保留 PID 与原始楼层映射。无时区的论坛时间按 UTC+8 解读；不导入图片。

## 验证路径

1. 导入结构化样例，调用现有清洗、分块及文本仓储代码。
2. 通过真实公共 MCP 执行 `search_archived_content(mode="keyword")`。
3. 用 SQL 探针按发言时间稳定分页，验证历史讨论完整枚举及去重。
4. 给旧帖添加一条明确标记的演练回复，验证它进入当日活动，历史补档不会混入当日发言。
5. 验证刷新前文本索引仍旧；显式重建后，通过 MCP 命中新回复 PID。
6. 修改这条回复，重建后旧文本不再命中，新文本命中同一 PID。
7. 重复导入和重建，断言发言数、分块数不增加。
8. 模拟 LLM 经内置 Agent 调用真实归档探测、关键词搜索、原文读取工具；摘要引用来自实际工具返回的原文。
9. 检查没有向量已索引分块、没有创建后台任务、源样例哈希未变，清理临时库。

演练进程及 MCP 子进程安装防护：禁止创建 embedding provider，禁止连接非本地网络。

## 2026-09-12 验证结果

- 导入 3 篇、85 条发言，得到 66 个文本分块，覆盖 62 条发言。
- 历史窗口通过 4 页取出《动画化情报》的全部 22 条发言。
- 新增、修订、重复导入及重建断言通过；最终为 86 条发言、67 个分块。
- 内置 Agent 实际完成 3 次 MCP 工具调用，生成带 PID 的模拟摘要。
- 向量已索引分块和后台任务均为 0；临时库已删除。

## 确认的缺口

- 正式索引 handler 仍绑定 embedding。本演练直接复用其文本加工函数和仓储，没有新增正式的纯文本索引任务模式。
- 新增与修改都需要脚本显式刷新整帖，尚无自动增量索引。
- 活动枚举与覆盖诊断是 SQL 探针，尚未提供给 Agent 使用的正式 MCP 接口。
- 现有分块仅覆盖样例中的 62/85 条发言。Agent 通过原文读取仍能看到完整内容，关键词索引不代表全部原文。
- 现有仓储将 `indexed_at` 作为非空写入字段，embedding 状态仍为 `pending`；演练报告单独计算文本覆盖，不把它冒充向量完成状态。
- 不验证真实 LLM 的自主规划、语义理解、自动主题发现、长期指标分析或大规模性能。
