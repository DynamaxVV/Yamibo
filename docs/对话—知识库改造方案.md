# 对话—知识库改造方案（现行总纲）

日期：2026-09-24。状态：产品目标与验收基线；部分能力已落入本地工作树，逐项实现位置和未验收边界见[实现指南](对话与知识库改造实现指南.md)。范围：仅讨论类帖子；本地离线副本的缺失不代表实际部署的缺失。

本文定义产品目标、范围与验收顺序。Agent 专项规定运行行为，日报与归档导出专项规定后台任务契约；实施架构和分步验证文档保留目标拆解与验收方法。各文档的当前用途见[实现指南](对话与知识库改造实现指南.md)。此前连续修订的全文保存在[历史草案](历史草案/对话—知识库改造方案-2026-09-23.md)。已有[讨论原文](对话与知识库页面—讨论原文记录.md)和[讨论样本复核](讨论类真实数据复核与方案修正.md)仅作背景与样例依据。

## 1. 产品目标和完成边界

一个用户可见的助手处理即时讨论问答、自动生成昨日讨论日报、明确的归档／导出委托；知识库让讨论和日报能找回、查看来源、继续追问。任务可以组合，例如“解释这期日报的争议，再把所选两篇归档并导出”。模型组织意图与内容，程序掌管范围、调度、授权、状态、引用和成果。

首个完整版本必须同时满足：

| 主线 | 交付结果 | 必须核实的事实 |
|---|---|---|
| 讨论问答 | 从未知问题发现讨论，或分析用户指定帖子；回答可打开原回复 | 候选、实际已读、未读范围分明；无向量时仍有可用的文本发现路径 |
| 归档／导出 | 用户确认目标和完整操作计划后，后台自动完成固定的归档／准备资料→导出链 | 重启后从回执续作，逐帖给出成功、失败、未执行及文件 |
| 昨日讨论日报 | 可手动生成某日，也可配置每日自动生成；知识库可查看历史并追问 | 目标日、规则快照、资料范围、统计口径、来源与部分结果状态可见 |

研究笔记的编辑／版本系统、全库向量重建、邮件、通用工作流和插件体系属于后续能力。首版只将“已选帖子”保留在会话或日报上下文；如果提供跨会话具名资料集，就需单独实现简单的具名 TID 集合，不把暂存选择称为“已保存资料集”。

## 2. 两页的具体职责

助手页保留 /chat：自然语言输入、范围条、即时提交状态、资料卡、日报卡、Job 卡、带来源的回答；可创建／暂停日报规则，可从知识库指定某期报告继续问或选择帖子委托操作。长任务离开页面后继续运行。连接状态与任务状态分别显示，模型描述不能充当执行进度。

知识库保留 /rag 兼容入口：首页突出讨论搜索、最近与历史日报、失败／资料缺口入口。日报详情有日期、板块、栏目、统计口径、关键回复、来源、版本和“问助手”；维护视图放索引与模型参数。讨论详情与列表可复用现有阅读入口，不建立第二套原帖管理。笔记和资料集在后续阶段增加。

最先验证的跨页流程：打开昨日讨论日报 → 追问某条 → 打开原回复 → 选择明确帖子归档／导出 → 回到知识库找回当期报告和任务结果。

从日报追问须绑定 report_id 与 report_revision、当期范围和来源回执。“解释这一期”沿用当期材料；“后来怎样”新建请求并显式扩大时间范围，不能偷偷改写原期报告。

## 3. 范围、来源和时间

即时问答有两种模式：

- 发现模式：冻结允许的讨论板块、时间和本地检索来源，在范围内找候选，再有界阅读。
- 指定资料模式：冻结 TID/PID；搜索、原文、旧笔记和其他可读入口都不能引入范围外的论坛证据。

模式和范围在创建 Run 时冻结，连同输入、报告版本纳入幂等请求。会话中随后修改只影响下一次 Run。日报有三个不同边界：当日统计只计目标日发表的讨论回复；为理解这些回复，可有界读取同一帖的更早背景，不计入当日数字；目标日后的更正单列时间，不能写作“昨天发生”。日期默认按 Asia/Shanghai 的当地自然日计算，界面明确展示时区。

待归档对象的候选可以来自用户给出的 TID、已选帖、本地元数据或受限论坛列表预览；这不授权任意网页抓取。写入对象另有独立操作计划和授权，研究阅读范围本身不是写权限。

## 4. 证据、事实与停止

每次成功原文读取由程序产生回执，至少包含 TID/PID、发表时间、实际读取片段／范围、是否截断和内容摘要标识。候选命中不是已读证据。回答引用本次回执；程序校验位置和范围，人工样例验收结论是否真的受原文支持。统计数字引用聚合回执，不要求模型读完所有回复；对“昨天发生了什么”的叙述引用实际读取的回复。日报保存最小来源片段和口径快照，删除聊天也不丢失报告依据。

相关资料足够时回答；缺关键上下文时针对性补读；到预算或重复检索不再增加有效材料时给部分结果；工具不可用时说明能力故障，不能称“没有讨论”；写入目标不明确时暂停该写入，请用户选定对象。停止助手只停止后续推理与工具调用，已创建 Job 保持独立状态。详细规则见 Agent 专项。

## 5. 日报和归档任务契约

日报期次按一条规则和一个目标日唯一确定；首次创建时冻结规则版本。执行重试沿用同一期，明确补报形成同一期的新成果版本。调度规则暂停、恢复、首日启动与有限补跑在日报专项定义。生成前读取同步检查记录；最新回复时间不能证明整段资料齐全。未知覆盖时可按规则交付标明范围的部分日报，绝不声称全论坛完整。

“归档后导出”是一个持久化的固定业务链，不依赖长时间占住 Chat Run，也不等待用户点第二次“继续”。一次授权覆盖冻结的对象和完整计划。默认逐帖执行依赖：成功的帖子继续导出，失败的帖子停止其后续步骤，汇总部分完成；用户明确要求整体成功时才采用整批停止策略。每个阶段记录 Job 和回执，重启后先核查旧状态再续作。普通开放式“归档完成后再研究”不在这条固定链内，未实现持久化续作时须明确告知用户需要再发起请求。

日报是否自动补抓资料、归档是否同步、导出是否补齐，均依规则或计划明确说明。日报自身不发起无界抓取。导出原帖包、导出日报、导出个人整理是不同成果。

## 6. 技术落点与阶段

沿用 React、FastAPI、PostgreSQL、应用层与 Daemon 的边界；Yamibo 在 RK3588 NAS Docker 内运行 embedded Pydantic AI，模型推理由云端或其它主机的 API 提供。实施时显式从 Hermes 切换并核对旧会话，发布前通过 ARM64 镜像和真实模型端点的工具约束测试；前端按实际能力展示入口。新增接口、表和 Job 类型以以下业务对象为核心，不建立通用 Agent 平台：

- 会话／Run：冻结模式、范围、引用来源及请求标识。
- 读取与统计回执：区分实际原文和聚合指标，供回答与日报引用。
- 操作计划：冻结目标、步骤、授权、逐帖 Job 和成果，能在重启后续作。
- 日报规则／期次／报告版本：区分规则修改、每日触发、执行重试和成果补报。

交付顺序按可验证闭环，而非按文档章节开发：

| 批次 | 完成范围 | 验收条件 |
|---|---|---|
| 0 方案收敛 | 本总纲与两份专项无相反指令；实施前将代码链接改为可复查的相对路径和版本 | 编码 Agent 不需跨文档猜优先级 |
| 1 反馈与讨论问答 | 即时消息、连接恢复、独立加载；发现／指定两模式，文本检索、补读与来源；选帖交给助手 | 无向量仍能找讨论并正确回答；长 Job 执行时可继续短查询 |
| 2 完整归档／导出委托 | 目标解析、完整计划授权、固定阶段衔接、回执恢复、最终文件 | 关闭页面或重启后仍能交付；失败帖子不阻塞成功帖子 |
| 3 手动日报 | 日期与板块、同步检查、候选与摘要、统计和原文两类证据、保存与追问 | 旧帖新回复、重复模板、后续更正和部分资料均正确表达 |
| 4 每日规则 | 创建／暂停、自动期次、有限补跑、失败恢复、规则与成果版本 | 连续生成；修改规则不制造重复期次 |
| 5 可选整理 | 具名资料集、笔记编辑、版本及语义增强，按真实使用加入 | 不阻塞前四批次 |

第 4 批次完成，才是当前三条主线的首个完整版本。前面每批可独立发布但不可代称全部目标完成。

## 7. 核心验收与实施边界

用真实讨论形态验收：有初始说法与后续更正时必须补读再回答；长年旧帖昨日有新回复时按昨日活动统计，背景内容另列；重复填表活动不能仅靠回复量冒充“值得看”。本地离线样本只验证内容结构，实际环境的数据覆盖和性能另行核实。

边界测试包括：指定三帖不能引用第四帖；同一请求标识改范围返回冲突；断线恢复不重复 Job；日报规则修改、停机补跑和迟到资料不会产生多个逻辑期次；归档成功、导出失败时保留归档事实并报告部分完成；模型或检索失败不能留下无限等待。浏览器还需验证 401、超时、窄屏、后台长 Job 与同时短查询。日志避免保存凭据和大段原文。

本方案保留产品目标，不是当前完成清单。2026-09-26 已有相关本地代码、前端入口和 Alembic 迁移；详细位置及尚未核实事项见[实现指南](对话与知识库改造实现指南.md)。本文件未证明线上数据库已迁移、线上容器已更新或 RK3588 部署已通过。
