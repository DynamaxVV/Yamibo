# 日报 V2：从逐帖摘要到有证据的社区编辑稿

状态：日报内容目标及实施记录。2026-09-26 的代码结构与现状见[对话与知识库改造实现指南](对话与知识库改造实现指南.md)；案例基于本地历史样本。

## 问题与目标

本节描述本方案最初的问题基线：当时日报主要呈现活跃榜和短摘要。此后已增加当日楼层分布采样、旧帖背景、专题正文与引用渲染、模型独立审稿和来源校验。当前版本拆分为 facts、coverage、editor、rendering 和 job service 模块；样本语义仍须对照原文人工审阅。

目标：读者用三分钟知道当天讨论了什么、具体说了什么、新信息在哪里、哪些意见有分歧、哪些帖子值得继续读。计数是选题依据，不能代替正文。

## 最终内容与界面

1. 今日速读：3—5 条具体信息，每条能直接回答“发生了什么／争论什么”，点击进入专题。
2. 重点专题：通常 3—5 个。每个包含明确标题、讨论缘起、2—4 个具体观点、支撑楼层、分歧或未解问题、阅读价值。按主题合并多个帖子，但不把不同作品或相反观点混成共识。
3. 新发现：少回复但信息量高的作品推荐、活动资讯、资料整理。没有可靠内容就不生成该栏目。
4. 延续讨论：有可比较历史证据时说明新增了什么；没有前日资料则不输出涨幅或“风向变化”。
5. 统计与方法：活跃榜、覆盖范围、采样限制折叠展示。

专题卡默认显示实质性摘要和两三条具体观点，而非只显示标题、标签、数字。展开后看到短摘录、TID/PID、时间和上下文。支持“围绕该专题继续问”，传入已保存的专题与证据范围。

## 日期口径：新帖与旧帖的新回复同等纳入

日报的基本单位是目标日内发生的讨论活动，不是目标日创建的帖子。按板块时区计算半开时间窗口 [当天零点，次日零点)，分别筛选新主题与新增楼层，再按 TID 合并候选。

- 当日新帖：展示发帖内容与当日回复；没有回复但有信息价值的新帖也可入选。
- 旧帖新回复：展示当天新增观点、信息、纠正或争论进展；首帖及此前楼层只作明确标注的背景。
- 旧帖仅有正文编辑：不算新增回复。有可验证的修改时间与版本差异时，可以单列“内容更新”；否则不推断为当日发生。
- 没有当日活动的旧帖：只可作为关联背景，不进入当日活跃榜。

统计分别展示新主题数、旧主题活跃数、活跃主题总数、当日楼层数。新帖与旧帖分类按主题创建时间互斥；当日楼层数包括首楼时须明示，“新增回复数”应排除首楼。无法确认主题创建时间或楼层角色的数据单列未知，不能强行归类。跨帖用户人数必须全局去重。

采集时必须兼顾两条路径：按发帖时间发现新帖，按最后回复时间发现旧帖活动，再读取相关楼层按实际发布时间过滤。最后回复时间只能用于发现候选，不能替代当天楼层证据。历史补报不能假定按当前最后回复时间翻几页就覆盖过去某一天；应依赖留存快照、当日楼层索引或明确范围的历史扫描，并如实记录覆盖。

旧帖分析输入分为 background（此前必要上下文）与 day_delta（当日新增楼层）。新回复引用的前文按需补读；引用文字不能再次计为当天的新观点。只有核对前文后才能写“首次提出”“观点转变”或“达成共识”；上下文不足时只写“当天回复涉及……”。长期专楼按议题拆分，避免整个专楼占据一个笼统摘要或挤掉其他选题。

专题卡标注“新帖”或“旧帖新讨论”，同时展示主题创建日期和日报日期。旧帖卡正文固定回答：此前在谈什么（简短背景）、今天新增了什么（主体）、新增内容是否改变此前认识（有证据才写）。同一主题不在两类重复计数。

验收增加：旧专楼当天多条回复、新帖零回复、跨午夜回复、当天引用旧楼层、后续编辑正文、历史补报中当天活跃但如今排序很靠后的旧帖。要求不漏掉已覆盖范围内的旧帖活动，也不把背景摘要包装成当日新信息。

## 生成流程

1. 冻结范围：板块、日期、时区、采集截止时间；沿用确定性统计与来源回执。
2. 多路候选：活跃主题、新发主题、低回复高信息候选分别取样并去重。初版采用透明配额，不以复杂加权分数假装精确。只处理讨论类内容，资源发布与闲聊显式分类。
3. 分批阅读：首帖作背景；当日楼层按时间段覆盖，补充被引用楼层和后段回复。长内容切块读，记录遗漏与截断；不用最早 30 条代替整天观点。
4. 帖内提取：输出具体主张、所属说话者、支持／反对／补充关系、事件时间、证据 PID 与原文范围。引用别人的文字不重复计为当前作者的立场。
5. 跨帖聚合：按作品、事件和议题生成专题。允许一个作品有多个专题；每个归并保留来源，防止同名或仅关键词相似导致误合并。
6. 补读：对无证据主张、分歧不清和前后指代缺失调用现有读取工具；不为凑栏目无止境检索。
7. 编辑：根据已核验的专题输出概览与正文，正文顺序按信息价值和多样性决定，统计排名单独保留。
8. 验收：程序验证引用归属、日期与数值；独立模型检查原文是否真的支持表述、是否遗漏限制。失败则局部重写；仍失败时删除该主张，保留可用专题。
9. 持久化：保存报告版本、专题、中间分析、模型版本、证据散列与审核结果，支持失败阶段续跑；网页与 Markdown 使用同一结构化报告渲染。

Pydantic AI 保持不变，用分阶段结构化调用完成。无需多个常驻 Agent；RK3588 负责调度、数据库与渲染，推理由已配置的外部 API 承担。并发、读取量与超时放在工具及任务执行层。

## 数据结构收口

DailyReportV2 包含 overview、topics、discoveries、continuations、stats、coverage。
Topic 包含 title、what_happened、claims、perspectives、open_questions、source_tids。
Claim 包含 text、kind（事实／观点／编辑推断）、evidence_refs、temporal_role、verification_status。
EvidenceRef 绑定 receipt_id、tid、pid、原文范围、发布时间、采集时间、可用的修改时间；不以发布时间证明正文历史版本。

RAG 不是每日生成的前置要求。当天数据由日期和板块确定性筛选；跨天背景补读、找关联旧专题时才按需检索。初版无需全库向量重建。

## 分步实施与验收

A. 先修渲染缺失，统一网页与 Markdown，证明模型已有内容不会丢失。
B. 增加分层阅读与帖内主张提取，以本次日期验证具体观点和引用准确性。
C. 增加跨帖专题与多路选题，比较新旧日报是否信息重复、漏掉有价值低热度内容。
D. 增加独立审稿与专题追问；最后接回自动定时任务。

以本次丰富样本、一个稀疏日和一个采集不完整日验收。要求数值与来源匹配、没有日期穿越、没有伪造共识；每个重点专题至少呈现两项有依据的具体信息。专题数量不作硬门槛：证据不足时允许更短，不能凑满。记录遗漏率、无依据表述数、重复专题数、运行时长和调用量，不能仅以 Job 成功或引用 ID 存在判定质量合格。

## 阅读体验修订：日报正文必须独立成立

读者不应通过点击来源才能知道发生了什么。专题以连贯报道写作：简短交代缘起，展开具体情节或信息，解释不同观点及理由，最后说明当天进展或尚无结论。证据充足时每专题约 250—500 字、3—5 段，长度只是写作参考，不能为凑字数编造或重复。

claims 保留为后台逐段证据结构，前台不逐条显示“当日讨论／用户观点”等技术标签。用户观点在句子中明确归属，背景和后续补充仍显式区分。引用汇总到专题末尾作为核查入口，不打断正文。其他动态直接给出消息内容，取消“推荐理由”式导读。长原文读取上限提高到 6000 字，仍披露截断，不把摘要厚度建立在补写猜测上。

验收增加“隐藏所有链接后阅读”：能否说清对象、发生的事情、具体细节和分歧理由；如果正文只剩“围绕某话题展开讨论”，则不合格。

## 分板块日报（用户确认范围）

日报按板块独立成篇，当前目标为海域区（33）、动漫区（5）、漫画区（30）。日期页面可以汇总三份日报的入口或简短导语，但统计、选题、正文与来源不可混成一个跨板块热榜。多板块请求由应用层拆分为各板块期次或子任务，分别记录完成／失败状态。

- 海域区：当天话题、具体经历、经验与建议、不同观点及其理由。避免把生活倾诉写成全体用户画像，不为追求热度过度放大私人细节。
- 动漫区：作品消息、剧情与人物分析、观众分歧、安利资料。剧透明确标注；区分观众解读与官方事实。
- 漫画区：当天章节／汉化／单行本／特典发布，以及新旧帖中的读者讨论。更新信息写清作品、章节或内容类别；剧情解读只在读到可靠文字或图像内容时生成。仅有标题和图片附件时，只报更新，不编造剧情摘要。

三类都纳入旧帖当日新回复。漫画区的发布活动与讨论活动分栏，不能把回复量当作作品质量，也不能为纳入漫画区而解除所有板块的内容过滤。

实施边界：已增加明确的板块准入策略，允许启用的漫画区（forum_id=30）文字归档进入日报候选与来源读取，并保留请求板块过滤。每板块独立出报时，应为每次期次只指定一个 forum_id；多 forum_ids 自动拆分为多篇、分别记录状态的编排仍未由当前接口统一完成。2026-09-26 的六份本地日期样例见[阅读索引](../artifacts/daily-briefs/multi-board-samples/阅读索引.md)。样例的人工修订不代表自动生成可省去语义审阅。
