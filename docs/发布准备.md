# 1.3 发布门禁与后续路线

> 版本：1.3.0 | 更新日期：2026-09-23

本文记录 1.3.0 发布门禁，并保留仍适用的 1.2 数据库迁移背景。当前操作事实仍以用户手册、部署运维指南、API 接口参考和智能体接口说明为准；线上状态必须现场检查。

当前发布门禁：工作区包含 `016_add_jobs_started_at` 数据库迁移。本次已允许修改生产数据库，
发布必须按[已批准数据库变更后的发布流程](部署运维指南.md#已批准数据库变更后的发布流程)
先备份、再停应用、执行迁移和验收。GitHub 提交本身不会改库；自动部署只有在启动新镜像时
才可能应用该迁移。

## 发布阻断项

以下项目必须在创建 1.3.0 tag 前全部满足：

- `pyproject.toml`、Python 包、FastAPI 和前端版本均为 `1.3.0`
- `uv run pytest` 全量通过，PostgreSQL 用例不能因缺少测试数据库而跳过
- `npm --prefix c run build` 通过
- `docker compose config --quiet` 和生产镜像构建通过
- 从空 PostgreSQL 数据库执行 Alembic 升级成功
- 使用实际备份完成一次隔离恢复演练；数据库与 `data/` 文件按 [部署运维指南](部署运维指南.md#postgresql-隔离恢复演练推荐) 分层验证
- Web、MCP 和 PostgreSQL 默认只绑定 loopback；公网访问必须经过 TLS 和访问控制
- `.env`、cookie、数据库 dump、schema 快照及本地 Agent 状态不进入 Git 或镜像
- 前端目录迁移完整提交，不保留 `frontend/` 删除与 `c/` 未跟踪并存的状态
- `AGENTS.md` 与 `.yamibo/chat` 作为项目级 Agent 行为契约完成审阅并纳入版本；会话状态、回放和个人配置不得混入
- 图片回填保持关闭或 dry-run，直到在实际 NAS 备份库完成一次小规模验证

- `.omc/`、`.mimocode/`、`.tokensave/`、`.serena/`、编辑器配置等本地状态
- 已被 Vite 新构建替代的旧静态 hash 资产
- 文档中的过期目录名、SQLite-only 描述和失效命令
- 根文档与 MCP guide 的重复说明；根文档保留完整规范，guide 保留运行时摘要和链接

清理只针对版本控制和发布包，不自动删除本地备份或用户数据。

## 当前保留的已知限制

- Web 控制台和 MCP 服务本身不提供完整的互联网身份认证；默认 loopback 是安全边界
- daemon 与嵌入式 Web 仍可运行在同一进程
- 文件归档依赖本地或共享文件系统，不支持无状态多节点 worker
- SQLite 仅用于本地轻量模式；Discussion Trend 仍为 PostgreSQL-only
- 知识库、RAG 和讨论趋势是低优先级可选能力，不影响归档、阅读、导出和任务恢复
- Web Chat 是否保留取决于实际使用；外部终端已经满足需求时，不再为 Chat 维护额外运行时

## 1.x 优先改进

1. **P0 待 NAS 现场确认**：为 Web/MCP 配置统一认证、权限和速率限制；代码不假设反向代理已经提供这些能力。
2. **P0/P1 代码已完成，进入数据库迁移发布**：健康检查、独立 Worker 心跳、Job 执行时长和增量事件读取已可被外部终端验证；`016_add_jobs_started_at` 按部署流程执行并以 `alembic_version` 和实际列结构验收。
3. **P1 发布验收**：数据库初始化移到 Web 应用创建阶段，并统一 `read_system_status`、`read-system-status` 和 `/api/system/status` 读取契约；迁移后需完成 Web、Daemon、MCP（如使用）和只读业务抽查。
4. **P2 文档已补齐，NAS 现场待执行**：按 [隔离恢复演练](部署运维指南.md#postgresql-隔离恢复演练推荐) 使用实际 PostgreSQL 备份验证临时库，并检查当前队列、暂停状态和长期 sign-in Job；大规模 `data/` 优先使用只读快照和抽样校验。
5. **低优先级观察**：只有实际使用增加时，才重新投入知识库、趋势分析或 Web Chat。

Agent/LLM 运行时的目标分层、契约和验收阶段以 [LLM 原生运行时路线图](LLM原生运行时路线图.md) 为准。本节只保留发布优先级摘要，避免在发布门禁文档中维护第二套设计。

## 2.0 候选范围

- 对象存储与无状态 worker
- 多租户和细粒度数据权限
- append-only 采集快照、回复关系图和可复现数据挖掘管线
- 多 Agent 协作、预算控制和模型路由

这些项目不应阻塞 1.3，也不应以未稳定的实验接口进入 1.3 公共契约。
