# 知识库本地演练

使用现有归档样例，检查数据导入、索引任务、公共 MCP、内置 Agent 和更新后的检索链路。
演练只模拟 LLM 与 embedding，不访问外部模型或论坛。

## 运行

在仓库根目录运行：

```bash
uv run python scripts/demo_knowledge_pipeline.py
```

默认读取当前配置中的本地 PostgreSQL 连接，要求有创建测试数据库的权限。
脚本只接受 localhost / 127.0.0.1 / ::1，创建随机命名的独立数据库，结束后删除。
仅在隔离库执行当前版本迁移；不更新原数据库，不运行后台任务消费者。

可使用 `--sample-root /path/to/threads` 指定示例根目录，以及
`--output /path/to/report-directory` 指定报告目录。默认报告保留在系统临时目录。
所选样例为 TID 553545、36025、572373；文件缺失会直接报错。

## 演练内容

1. 导入三篇帖子。保留 PID、正文、作者和引用；仅在演练库按时间排序并生成连续楼层。
   原始楼层到演练楼层的映射和源文件哈希写入报告；不复制图片。
   无时区时间按论坛 UTC+8 解释，源文件不变。
2. 经真实 stdio MCP 创建索引任务，仅执行刚创建任务的实际 handler，并通过 MCP 检查完成状态。
3. 用关键词、向量、混合三种模式检索。
4. 使用现有 `EmbeddedChatService` 与模拟 `FunctionModel`，实际调用三次 MCP 工具，
   从返回的原文生成带 PID 的演示摘要。
5. 向旧帖新增一条明确标记的测试回复，检查按发言时间查询和索引重建前后的差异。
6. 再导入相同内容并再次索引，检查重复计数以及 embedding 输入数量。
7. 模拟 embedding HTTP 503，检查部分完成状态、文本检索可用性与恢复重建。

## 如何理解结果

`summary.md` 是人工阅读摘要；`report.json` 包含工具响应、事件、统计、输入计数及断言结果。
`passed: true` 表示以上演练检查通过，不表示新的知识库架构已经实现。

- 模型决策是脚本规定的，embedding 是 512 维确定性哈希向量；不证明语义检索质量、模型判断或总结准确率。
- 活动枚举和覆盖查询是脚本里的 SQL 探针，尚未作为公共 MCP 能力交付。
- 新回复由本地快照模拟，不验证远端抓取；索引仍由脚本显式发起。
- 当前索引按整帖重建。即使内容不变，仍会生成向量；演练记录此缺口，不伪装成增量更新成功。
- 清洗与分块可能排除短回复。报告列出导入发言数和进入索引的发言数，不能把检索结果当成全部讨论。
