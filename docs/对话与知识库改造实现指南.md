# 对话与知识库改造实现指南

更新日期：2026-09-26。本文记录当前仓库中的代码职责、主要调用路径、资料边界和文档入口。它描述的是本地工作树，不代表线上部署已更新。产品目标仍以[改造方案](对话—知识库改造方案.md)为准；与代码不一致时，按本文标出的目标/现状边界判断，不把计划写成完成事实。

## 用户入口

| 页面 | 用户能做什么 | 前端入口 |
|---|---|---|
| 助手 | 用自然语言查讨论、阅读指定帖子、带引用总结、查看日报、提出归档/导出计划，并管理会话 | `/chat`，`c/src/pages/Chat.tsx` |
| 知识库 | 直接检索讨论与 RAG 索引，查看研究结果和日报期次；可从指定日报版本创建带冻结范围的助手会话 | `/rag`，`c/src/pages/Rag.tsx` |
| 设置 | 配置模型并进行连通测试，编辑项目 Agent 指导；审阅 Agent 提出的 Skill 修订 | `/settings`，`c/src/pages/Settings.tsx` |

助手处理意图和组织答案。知识库帮助找回归档讨论、RAG 检索结果及已保存日报。**助手检索不要求先建向量索引**：讨论发现走受限的数据库搜索，再读取确切楼层；知识库里的 RAG 索引仍是独立检索能力，用于混合搜索和索引维护。

## 请求路径与职责

```text
Chat / Knowledge UI
  → FastAPI routers：校验请求、会话所有者与访问范围
  → EmbeddedChatService：Run、事件流、上下文和模型调用
  → Pydantic AI + 每个 Run 单独构建的 MCP server
  → 项目工具/Skill → application queries/commands → repositories
  → PostgreSQL；长任务由 Job + Daemon handler 执行
```

| 责任 | 当前实现位置 |
|---|---|
| 对话会话、Run、停止、审批、事件和 SSE | `services/embedded_chat/runtime.py`、`store.py`；`web_fastapi/routers/chat.py` |
| Run 级工具限制、权限、来源与操作回执 | `services/embedded_chat/policy.py`、`mcp.py`、`tool_server.py` |
| 讨论搜索、精确楼层阅读与引用验证 | `application/discussion_discovery_queries.py`、`assistant_evidence_queries.py` |
| 归档/导出计划、审批与阶段推进 | `application/assistant_operation_plans.py`、`assistant_operation_execution.py`；`web_fastapi/routers/assistant_operations.py` |
| 日报事实、覆盖检查、编辑、渲染和期次读取 | `application/daily_brief_facts.py`、`daily_brief_coverage.py`、`daily_brief_editor.py`、`daily_brief_rendering.py`、`daily_brief_service.py`、`daily_brief_report_queries.py` |

| 项目指导、Skill 和提案审核 | `services/embedded_chat/SOUL.md`、`skills/`、`guides/`、`project_skills.py`、`skill_proposals.py`；Web 设置与 `skill_reviews` API |

Run 级 MCP server 只做工具注册与参数面；权限和业务规则由 `RestrictedTools`、`Policy` 及应用服务检查。公开 MCP 工具按需通过 `discover_public_tools`、`describe_public_tool`、`call_public_tool` 使用；项目 Skill 只补充工作方法，不会授予工具权限。

## 讨论检索、引用和上下文

1. 创建 Run 时冻结板块、帖子、楼层、时间或日报版本等范围。用户本轮明确给出的论坛板块名称/ID会转成受限目标；它不能放宽此前已经冻结的帖子/楼层边界。
2. `find_discussions` 返回符合范围的候选。短词或索引能力不足时，结果会说明只查标题或部分结果；发现结果本身不算已读证据。
3. `read_discussion_source` 按 `(tid, pid)` 读取指定楼层，生成来源回执；回答结束前用 `validate_discussion_citations` 检查引用仍对应本次 Run 实际读过且内容未变的来源。
4. 模型上下文复用范围兼容的普通对话文字。旧 Run 中含工具结果、文件操作或引用时，不把旧工具响应重新当作当前证据；操作事实通过 `read_operation_history` 恢复，原文须在新 Run 里重新读取。

因此，同一会话在界面上保留完整记录，并不代表模型会把旧 Run 的工具结果当作新证据。切换论坛、帖子或日报版本会创建不同范围；需要续问旧日报时，服务端从日报版本快照创建受限范围。

## 日报与两类定时任务

日报包含目标日新帖和旧帖当日新回复。`daily_brief_facts` 负责固定统计与候选排序，coverage 记录有界资料准备的结果，editor 只对已读取文字组织专题，rendering 输出面向读者的 Markdown 和来源链接。完整覆盖不能由某条帖子的“最后回复时间”单独证明；资料不足时应保留不完整状态。

当前有两条不同的定时路径：

- **日报规则**：`/api/daily-rules` 管理板块、时区、执行时间、准备截止时间和预算；`schedule_due_daily_briefs` 按规则创建日报期次及 `daily_brief_report` Job。
- **通用定时任务**：`/api/settings/scheduled-tasks` 管理一次性或 cron 时间表；当前动作白名单仅包含 `archive_thread`。它不是任意提示词调度器，也不负责日报规则。

这两条路径在 Daemon 同一调度循环里分别执行，但规则、期次、幂等键和处理逻辑各自独立。不要把通用 Job 队列、定时规则和日报期次视为同一种记录。

## 归档与导出

Agent 对选中的完整帖子提出操作计划。服务器冻结动作、帖子、图片要求和导出策略；计划经独立批准后，由 Daemon 按阶段创建/复用归档及导出 Job。批准绑定计划版本与摘要；修改目标后须重新批准。Job 入队不是执行完成，最终状态与文件由计划/Job 读取接口核实。帖子和来源搜索不等于操作授权。

归档操作本身仍复用现有 archive commands、Job repository 与 Daemon handlers。Agent 不直接运行 SQL、Shell 或任意 URL，也不能凭自己的答复宣称操作完成。

## 主要 API 和数据迁移

| API 前缀 | 用途 |
|---|---|
| `/api/chat` | Sessions、Runs、事件、来源回执与工作文件 |
| `/api/knowledge`、`/api/rag` | 讨论检索、研究接口、索引与混合搜索 |
| `/api/assistant/operation-plans` | 计划的读取、批准、取消和状态 |
| `/api/daily-issues`、`/api/daily-rules` | 日报期次和定时日报规则 |
| `/api/settings/scheduled-tasks` | 白名单归档时间任务与执行记录 |
| `/api/settings/models`、`/api/settings/model-test` | 模型配置和连通测试 |
| `/api/settings/agent-guidance` | 设置页维护的项目 Agent 指导 |

相关 schema 迁移集中在 `alembic/versions/017_embedded_chat.py` 至 `029_scheduled_tasks.py`。正式迁移仍通过项目 `yamibo-init-db` 入口执行；迁移文件的存在不等于任何运行数据库已升级。
