# 对话界面设计文档

> 版本：0.13.0 | 更新日期：2026-07-10

## 1. 设计目标

对话界面本身**不直接实现模型推理**，而是作为外部 Hermes 的对话入口。页面的职责是把用户输入、当前页面上下文和会话状态整理好，再交给外部 Hermes 处理；Hermes 再按自身能力自主调用 Yamibo MCP 完成交互。

因此，这个页面的目标不是替代现有浏览和管理页面，也不是内置 RAG 或本地检索能力，而是提供一个稳定、轻量的交互入口，让用户能够：

- 发起和继续外部 Hermes 对话
- 看到当前会话绑定的页面上下文
- 追踪 Hermes 返回的消息、引用和操作结果
- 从帖子、系列或远端页面自然跳转进入对话

## 2. 页面定位

建议路由为 `/chat`。

该页面处于“交互入口”层级，属于前端壳层，不承担推理、检索或问答逻辑。典型使用场景包括：

- 围绕某个 `tid` 发起自然语言对话
- 围绕某个系列、板块或远端帖子继续追问
- 让外部 Hermes 自主调用 Yamibo MCP 工具完成浏览、读取、归档或查询
- 查看 Hermes 返回的流式回复与最终结果

注意：
- **与 RAG 页面无直接耦合**
- **不要求页面自己组织检索证据**
- **不在前端实现模型上下文拼装规则之外的推理能力**

## 3. 页面结构

### 3.1 主体布局

页面建议采用三段式结构：

1. **顶部上下文栏**
   - 当前对话标题
   - 会话状态摘要
   - 当前绑定对象摘要（如帖子、系列、远端页面）
   - 清除上下文 / 切换上下文入口

2. **中间消息区**
   - 按时间顺序展示用户消息与 Hermes 回复
   - 回复中支持 Markdown、代码块、引用块和工具结果摘要
   - 长回复可折叠显示，默认展开首段摘要

3. **底部输入区**
   - 多行输入框
   - 发送按钮
   - 继续追问 / 重试 / 停止生成
   - 是否附带当前上下文的开关

### 3.2 交互状态

页面至少需要覆盖以下状态：

- 空会话
- 首次加载中
- 正常对话
- 流式输出中
- 失败重试
- 无上下文对话

## 4. 对话数据模型

建议将一次会话抽象为以下信息：

- `conversation_id`：会话标识
- `title`：会话标题
- `messages`：消息列表
- `context`：上下文对象，如 tid、series_id、forum_id、remote_tid、页面类型
- `created_at` / `updated_at`
- `mode`：普通问答、帖子辅助、远端预览辅助、系列辅助

消息建议包含：

- `role`：user / assistant / system
- `content`：正文
- `attachments`：Hermes 返回的工具结果摘要、引用或链接
- `status`：streaming / complete / failed
- `citations`：可追踪来源片段（如有）

## 5. 主要交互流程

### 5.1 从帖子进入对话

用户在帖子详情页点击“发起对话”后：

1. 跳转到 `/chat`
2. 自动注入帖子上下文
3. 输入框默认提示“基于当前帖子提问”
4. Hermes 根据用户输入，自主决定是否调用 Yamibo MCP 读取帖子、楼层或相关资源

### 5.2 从系列或远端页面进入对话

用户在系列详情页或远端帖子页点击“发起对话”后：

1. 打开 `/chat`
2. 将当前页面最小必要上下文带入会话
3. Hermes 根据问题自主判断调用哪些 MCP 工具
4. 页面只负责展示 Hermes 的回复与会话状态，不直接执行业务推理

### 5.3 纯对话模式

不绑定任何帖子或页面对象时：

- 仅展示通用对话能力
- 不自动附带本地上下文
- 适合作为外部 Hermes 的全局入口

## 6. 结果展示规范

### 6.1 回复内容

回复建议遵循以下展示顺序：

1. 简短结论
2. 关键依据或操作结果
3. 展开说明
4. 引用或工具结果摘要（如有）

### 6.2 证据与引用

如果 Hermes 返回了来源信息，应展示：

- 来源类型：帖子、楼层、远端页面、MCP 工具结果
- 来源标识：tid、floor、url、resource id、tool name
- 可点击跳转：本地帖子详情或远端页面

### 6.3 错误提示

需要区分三类错误：

- 上下文加载失败
- Hermes 会话 / 流式连接失败
- 工具调用链路失败

错误提示应尽量保留可恢复信息，例如“重试”“切换上下文”“重新连接 Hermes”。

## 7. 接口约束

对话页建议依赖以下能力：

- 与外部 Hermes 建立流式对话连接
- 传递最小必要上下文
- 获取对话历史
- 显示 Hermes 返回的工具调用结果与引用
- 支持停止生成与重试

页面不应假设模型由 Yamibo 内部托管；Hermes 侧可通过其自身机制调用 Yamibo MCP 完成交互。

## 8. 设计原则

- **Hermes 主导**：推理与工具调用由外部 Hermes 完成，Yamibo 只提供对话入口与上下文
- **上下文最小化**：前端仅传递会话必要信息，不提前替 Hermes 组织复杂检索流程
- **结果可见**：Hermes 的回复、工具结果和引用应清晰可追踪
- **非破坏性**：对话页面默认只读，不直接修改归档数据
- **解耦**：页面与 RAG / 归档 / 远端浏览页面松耦合，避免把对话页做成“第二套检索系统”
