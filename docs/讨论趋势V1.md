# Discussion Trend V1

Discussion Trend V1 为 Yamibo 历史论坛分析提供一套仅支持 PostgreSQL 的趋势事实层、证据检索能力和报告工具。

> 文档同步版本：1.3.1 | 更新日期：2026-09-23

## 范围

- 支持的后端：仅 PostgreSQL。
- 不支持的后端：SQLite 不支持 trend mart、topic evidence、forum evidence pack 和 discussion report。
- 首批支持的分区：`forum_id=5`（动漫区）和 `forum_id=33`（海域区）。
- Trend Mart 是统计事实底座，不是 agent 能力边界。
- 非趋势类论坛研究在 V1 中就是一等能力，入口是 evidence pack 和 forum research report。

V1 包含：

- trend mart 构建任务
- partition/topic/user 趋势查询
- 支持 RAG 或 SQL fallback 的 topic evidence 检索
- 面向非趋势问题的 forum evidence pack
- trend report artifact
- forum research report artifact

## 0.12.1 同步说明

本轮对 V1 的主要收口如下：

- 行为修正
  - 同一 `(forum_id, start_date, end_date, version)` 允许重复重跑；current run 的切换由 `discussion_current_indexes` 负责
  - topic evidence 的 SQL path 支持 thread-level assignment，不再要求 assignment 必须绑定到单个 `pid`
  - `discussion_user_daily.topic_count` 的聚合键修正为真实 `bucket_date + user_key`
- 代码收敛
  - query/report 共用的 partition/topic/user 聚合和 RAG evidence shaping 统一到共享 helper
  - trend 相关 CLI 查询入口改为表驱动注册，减少重复分支

V1 不包含：

- topic candidate 持久化
- alias dictionary 管理
- controversy score
- topic co-occurrence
- user topic profile
- LLM summary generation

## Agent Tool 返回封装

所有面向 agent 的输出都使用以下封装之一：

```json
{
  "ok": true,
  "data": {}
}
```

```json
{
  "ok": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Human readable message",
    "agent_hint": "Actionable retry hint",
    "retryable": false
  }
}
```

`warnings` 是稳定的 code，位于顶层 `warnings`，也可能会在 `data.warnings` 中重复一份。

## Tool Contract

### `create_discussion_trend_index_job`

参数：

- `forum_id`
- `start_date`
- `end_date`
- `version`，默认 `trend-v1`
- `thresholds`，可选对象
- `retention_success_runs`，默认 `3`

成功返回：

```json
{
  "ok": true,
  "data": {
    "job_id": "job-123",
    "job_type": "discussion_trend_index",
    "created": true,
    "forum_id": 5,
    "start_date": "2014-11-01",
    "end_date": "2014-11-30",
    "version": "trend-v1"
  }
}
```

说明：

- 这里只写入后台任务
- 需要 daemon 执行
- failed run 不得替换 current pointer
- succeeded run 可以在相同窗口上成为新的 current run

### `create_discussion_trend_report_job`

参数：

- `forum_id`
- `start_date`
- `end_date`
- `version`，默认 `trend-v1`
- `period`，可选 `daily|monthly|custom`
- `format`，可选列表，默认 `["json", "markdown"]`

成功返回：

```json
{
  "ok": true,
  "data": {
    "job_id": "job-234",
    "job_type": "discussion_trend_report",
    "created": true,
    "forum_id": 5,
    "start_date": "2014-11-01",
    "end_date": "2014-11-30",
    "version": "trend-v1",
    "report_kind": "trend_report"
  }

```

说明：

- 依赖同一窗口上已有 current 且 succeeded 的 trend run
- JSON 和 Markdown artifact 存在 `discussion_report_runs`

    "job_type": "discussion_trend_report",

### `get_discussion_topic_evidence`

参数：

- 基础窗口字段
- `topic_id` 或 `topic_label` 二选一
- `top_k`
- `mode`，可选 `auto|sql|rag`

成功返回：

```json
{
  "ok": true,
  "data": {
    "forum_id": 5,
    "run_id": 12,
    "topic_id": 7,
    "topic_key": "anime:yuri",
    "topic_label": "百合动画",
    "retrieval_mode": "sql",
    "query_terms": ["百合动画"],
    "items": [
      {
        "tid": 572313,
        "floor": 18,
        "content": "..."
      }
    ],
    "retrieval_diagnostics": {
      "rag_error": "no results",
      "sql_fallback_used": true
    }
  },
  "warnings": ["DISCUSSION_RAG_SQL_FALLBACK_USED"]
}
```

RAG fallback 行为：

- `mode=rag`：当 RAG 无法服务请求时，返回 `DISCUSSION_RAG_EVIDENCE_UNAVAILABLE`
- `mode=auto`：优先使用 RAG；失败后回退到归档楼层 SQL evidence，并发出 `DISCUSSION_RAG_SQL_FALLBACK_USED`
- `mode=sql`：跳过 RAG，直接使用归档楼层 SQL evidence
- SQL evidence 同时支持：
  - floor-level assignment：assignment 直接绑定 `pid`
  - thread-level assignment：assignment 只绑定 `tid`，再从线程楼层中选代表证据

### `get_forum_evidence_pack`

参数：

- `forum_id`
- `query`
- 可选 `start_date`、`end_date`
- `top_k`
- `mode`，可选 `auto|sql|rag`
- `intent`，可选 `general_research|slang_usage|community_atmosphere|topic_investigation|trend_context`
- `require_current_run`，默认 `false`

成功返回：

```json
{
  "ok": true,
  "data": {
    "forum_id": 33,
    "query": "黑话",
    "intent": "slang_usage",
    "retrieval_mode": "sql",
    "items": [
      {
        "tid": 600001,
        "floor": 3,
        "content": "..."
      }
    ],
    "retrieval_diagnostics": {
      "rag_error": "vector unavailable",
      "sql_fallback_used": true
    },
    "diversity": {
      "distinct_tid_count": 1
    },
    "limitations": [
      "sql_fallback"
    ]
  },
  "warnings": ["DISCUSSION_RAG_SQL_FALLBACK_USED"]
}
```

行为说明：

- `mode=auto`：先尝试 RAG/hybrid，再回退到原始楼层 SQL 搜索
- `mode=sql`：直接走原始楼层 SQL 搜索，不要求 current trend run
- `mode=rag`：当 RAG 不可用或无结果时，返回 `DISCUSSION_RAG_EVIDENCE_UNAVAILABLE`
- `require_current_run=false`：即使没有 current mart window，非趋势研究也仍然可用

### `get_discussion_report`

参数：

- 基础窗口字段
- `format`，可选 `json|markdown`
- 可选 `report_kind`

成功返回：

```json
{
  "ok": true,
  "data": {
    "forum_id": 5,
    "run_id": 12,
    "reports": [
      {
        "report_kind": "trend_report",
        "report_json": {
          "metadata": {
            "report_kind": "trend_report"
          }
        },
        "created_at": "2026-07-01T10:00:00Z"
      }
    ]
  }
}
```

行为说明：

- 这里只读取已存储的 artifact
- 如果传入 `report_kind`，则按类型过滤
- 如果尚未生成 artifact，则返回 `DISCUSSION_REPORT_NOT_FOUND`
- CLI `discussion-report` 当前默认读取 JSON artifact；`format` 参数主要用于 MCP / application 层

## Forum Research Agent Routing Contract

Trend Mart 是统计事实底座，不是 agent 研究能力的上限。

- `trend_analysis`
  - 使用 `get_discussion_partition_trends`
  - 使用 `get_discussion_topic_trends`
  - 使用 `get_discussion_user_trends`
- `topic_investigation`
  - 先看 topic trends
  - 再使用 `get_discussion_topic_evidence`
- `slang_usage`
  - 使用 `get_forum_evidence_pack(intent="slang_usage")`
- `community_atmosphere`
  - 如果有趋势数据，先看 partition 和 user trends 的宏观背景
  - 再使用 `get_forum_evidence_pack(intent="community_atmosphere")` 获取楼层证据
- `general_research`
  - 使用 `get_forum_evidence_pack`
  - 再配合 archive read tools 追到具体 thread
- `reporting`
  - 趋势问题：使用 trend report artifact
  - 非趋势问题：使用 forum research report artifact

## 已知限制

- 当前归档快照存在近期数据缺口，这是预期现象。
- 当 topic 支持度过低时，topic ranking 可能退化为仅输出聚合趋势。
- RAG 覆盖可能不完整；SQL fallback 可用，但语义能力更弱。
- Discussion Trend V1 不支持 SQLite。
- 如果测试 helper 会启动一个独立 server process 且目标是 SQLite，必须同时固定 `YAMIBO_DB_BACKEND=sqlite` 并清空 `YAMIBO_DB_URL`，否则继承到的 PostgreSQL 配置可能污染子进程。
